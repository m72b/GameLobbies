# Changelog

All notable changes to Game Lobby are listed here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and versions follow [Semantic Versioning](https://semver.org/).

## [Unreleased]

### Game details without a key: Wikidata, Wikipedia and Wikimedia Commons
- New built-in game details source that needs no key: release date, platforms, developer, publisher and genres from Wikidata (CC0), the first paragraph of the English Wikipedia article when IGDB has no description (shown with *From Wikipedia*, a link to the article and CC BY-SA 4.0), and free logos, plus a cover where a free one exists, from Wikimedia Commons, each credited with author, licence and a link to its file page. On by default; **Use Wikipedia & Wikidata (no key needed)** in **Settings → API keys** and **Settings → Playtime and Stats** turns it off.
- Only free images: a Commons file is used only when Commons hosts it under public domain, CC0, CC BY or CC BY-SA (never fair use, NonFree, NonCommercial, NoDerivatives, GFDL-only or unclear licences), and only from the Commons upload folder.
- Only fills what is missing: IGDB and your own values come first; titles, genres, covers and logos you set are never changed. Wikimedia logos are fallbacks behind Steam and SteamGridDB; Wikimedia covers are never set on their own and are offered under **Customize → Cover** (small ones marked *Low resolution*). A Wikimedia image is only shown with its credit: images restored from a backup are checked on Commons again first, and chosen images that are no longer free files on Commons are removed.
- Matching by Steam app ID or IGDB entry first (one batched query), editions count as their game, then by exact title; when several items match, Game Lobby asks instead of guessing (**Find details on Wikidata** on the game page, with **Use automatic match** to undo). **Customize** shows Commons logos under **Logo** and free covers under **Cover**.
- Requests go strictly one at a time (images too) to the four Wikimedia API hosts only (https, checked redirects, size caps, `maxlag`, Retry-After; a rate limit pauses all Wikimedia requests for 10 minutes), with a descriptive User-Agent; images go through the cover cache (Commons uploads only). Results are cached for 30 days (7 when nothing was found) and are not part of backups.

## [0.8.0] — 2026-11-22

### Store accounts and first-time setup
- New first-time setup inside the main window when the library is empty: welcome, the stores you use, how to use each (sign in, installed files only or skip), Steam sign-in and API key, library folders, optional keys, then **Finish and scan**. Every step can be skipped. Existing libraries get a dismissible **Add store accounts** banner instead.
- New **Settings → Accounts**: per-store status, **Sign in through Steam**, **Sync now**, **Sign out**, **Use** (Account or Installed files only) and **Run setup again**. GOG and Battle.net sign in too (below); Xbox and Epic Games are listed as coming in a later version; EA app, Ubisoft Connect and itch.io stay installed files only. Amazon and Humble account sign-in are not planned.
- **Sign in through Steam** opens Steam's sign-in page in your default web browser (approve with Steam Guard as usual); the password goes only to Steam. Steam returns the browser to a one-time address on this PC (`127.0.0.1`, random port), where Game Lobby checks the OpenID answer (nonce, endpoint, return address, signed fields, freshness, one use) and confirms it with Steam before the SteamID64 is saved in the existing encrypted owned-games setting, so the Steam Web API key is the only thing left to enter. The tab then shows a fixed page saying whether the sign-in was saved, Game Lobby comes to the front and stops listening (slow or idle connections don't hold it up; pressing the button again reopens the same page); cancel or 10 minutes also stop it (not while Steam's answer is being checked). Signing in to another Steam account removes the previous account's not-installed games; a sign-out during the check wins.
- The locked-down embedded sign-in window (InPrivate, host allowlist checked by the app and by WebView2, no popups, downloads, permissions, app links, context menu or browser shortcuts) is used by Battle.net; Steam and GOG sign in in the browser.
- **Installed files only** for Steam asks first, then pauses the owned-games import and removes the not-installed games it added (games with your data stay); saving Steam credentials again resumes it.
- **GOG account** (unofficial: GOG Galaxy's public app id, the way Heroic and Lutris sign in): **Sign in to GOG in your browser** opens GOG's sign-in in the default browser, where every GOG sign-in method works (e-mail, Google, Discord, ...). You paste the address GOG ends on (`embed.gog.com/on_login_success…`) into Game Lobby, which checks it strictly, exchanges the one-time code for GOG's tokens (kept encrypted, renewed on their own) and lists your games with their titles and GOG's playtime (a large library is covered over several syncs; counted like Steam's, with **Added from GOG** entries). **Not you? Sign out** appears next to the signed-in GOG name.
- **Battle.net account** (unofficial; reads the data Battle.net's own account pages use): **Sign in to Battle.net** opens Game Lobby's private sign-in window; when the account overview appears, the session is checked and kept encrypted, and the games on the account are listed, with launch links for well-known Blizzard and Activision titles. Battle.net's sign-in options (Google, Apple, Facebook, Discord, Steam, Nintendo, PlayStation, Xbox) work in that window: only those providers' exact sign-in sites are allowed, only for Battle.net, and the title shows the provider's site; Google may still refuse sign-in inside an app window. The window's diagnostic never receives form data (no request events, no post data or bodies kept). The window writes the kind of each page problem (script error class, blocked or failed request, HTTP error) to the log, as sites and paths only and never the page's messages, to find sign-in problems.
- For both: nothing already in the library is changed, removals wait for complete lists behind the mass-removal guard (an empty list after a full one is never believed), syncs run with scans at most every 6 hours and stop after 5 minutes, and **Sign out** / **Installed files only** remove the not-installed games they added. The sign-in notice names the account when the store reports it (GOG user name, BattleTag). A game that is owned but has nothing to launch says so when you press Play.
- The prototype freeze that protects Game Lobby's own window now runs from its first script instead of Tauri's app-wide setting, which also applied it to store sign-in pages and can break them.

### Security
- Every app command is now in the Tauri app manifest, and only the main window is granted them (`capabilities/default.json`); the backend also refuses commands from any other window, and the `lobby-cover` / `lobby-shot` protocols answer other windows with 403. Sign-in windows can call nothing.
- Store sessions (GOG tokens, Battle.net cookies) are sealed with Windows DPAPI per store; Battle.net cookies are filtered to its own cookie domains, GOG's token is sent only to GOG's API hosts, and both go only to the store's listed hosts over https (redirects checked hop by hop), and never reach the renderer, logs, backups or diagnostics (yes/no only).
- Logs and the diagnostics report also redact OAuth codes, `gamekeys`, every `openid.*` value, `Cookie` / `Set-Cookie` headers and JSON Web Tokens.
- Technical: new commands `accounts_status`, `accounts_sign_in`, `accounts_cancel_sign_in`, `accounts_sign_out`, `accounts_set_mode`, `accounts_sync`, `setup_get`, `setup_save` (enum inputs only); event `accounts:changed` (main window only); settings section id `accounts`. New `settings` row `setup` (not in backups) and `library_connections` rows `account:<store>`; no schema version change.

### Interface
- **Settings → Startup and Behavior** now works: **Launch on boot**, **Minimize to tray** and **Close to tray** (all off by default). Launch on boot writes a per-user Windows startup entry (`HKCU\...\Run`, value `Game Lobby`, the quoted program path plus `--autostart`, never `HKLM`) and starts minimized, in the tray when a tray option is on; it is checked at every start and on every settings change, so a moved program path is corrected and turning the option off removes the entry (the uninstaller removes it too). A tray icon (tooltip "Game Lobby", left-click opens the window, menu **Open Game Lobby** and **Quit**) exists only while Minimize to tray or Close to tray is on. Minimizing hides the window to the tray; the close button hides it and Game Lobby keeps running (playtime tracking continues), with a one-time hint the next time the window is shown. Quit from the tray, the side rail's Quit and update installs exit for real, and a second launch shows the hidden window.
- Technical: new stored settings `launchOnBoot`, `minimizeToTray` and `closeToTray` (booleans; older settings default to off); the `tray-icon` feature of the `tauri` crate; new event `tray:hint`. No new commands or permissions.

## [0.7.0] — 2026-11-19

### Statistics
- New **Statistics** view, opened from the side rail or the library bar (it replaces the **Recently played** view and button; **Play history** is unchanged). It opens in place of the library like Settings (**Back** or **Esc** to leave) with four tabs: **Overview** (all, installed, not installed, hidden and favorite games, total and average play time, total install size), **Completion** (played and not played), **Top playtime** (the 50 most played games with time and share of the total, sortable) and **Library** (games and share per store or custom launcher). Hidden games are left out unless **Include hidden games** is on. The average is over games with play time; games with several routes count once under the store shown on their card; installed games without a measured size are counted separately.
- Steam playtime: the Steam owned-games import now also saves the hours Steam reports (`playtime_forever`) for each owned game, so Statistics include time played outside Game Lobby. Per game the larger of tracked and Steam time counts (never the sum), the Overview says when Steam time is included and a tooltip shows both figures. It is stored apart from Game Lobby's own playtime, which is never changed, refreshed on each import, cleared by **Remove** and left out of backups.
- Steam hours everywhere: for every game with a Steam app id, **Play time** on the game page, the hours on library cards and the **Playtime** sort now use the larger of tracked and Steam time (a game with 165 h on Steam shows 165 h even if Game Lobby tracked 40 h); linked games use the largest figure across their Steam routes. **Last played** (page and sort) is the newer of tracked and Steam's `rtime_last_played`. **Last two weeks** and **First played** stay tracked-only. The library updates right after a Steam import.
- Added from Steam: the game page's Activity list and the full play history show one read-only entry per game, **Added from Steam · 125 h** (Steam's total minus what Game Lobby tracked, dated at the last sync, with a Steam icon and a tooltip with both figures). It is hidden when the difference is zero, is not a session (no edit, delete, share or export; **Sessions** counts real sessions only) and never changes tracked playtime or sessions.
- Technical: new read-only command `stats_store_times`; `tracking_stats` gains an optional `store` and counts Steam's figure in `totalSeconds` and `lastPlayed`; `sessions_page` gains `storeEntries` (first page only); `store_playtime` gains a nullable `lastPlayed` column (added in place when missing, older builds ignore it). Tracked tables (`games`, `play_sessions`) are not written.
- Technical: new read-only command `stats_summary` (one boolean argument, computed in one pass in Rust); new table `store_playtime(source, appId, seconds, updatedAt)` (added table, no schema version change; older builds ignore it).

## [0.6.0] — 2026-11-19

### Interface
- Settings now opens inside the main window instead of a separate window: the gear, **Ctrl+,** and every "open settings" link switch the library to Settings with its own section list; **Back** or **Esc** returns to the library where you were. Changes show in the library immediately.
- New **Settings → API keys** tab: the SteamGridDB key, the IGDB (Twitch) Client ID and Secret, and the Steam Web API key with SteamID64, each with what it unlocks, its status and **Add**, **Change** and **Remove**. **Add keys** opens a sheet from the right with all of them at once and short steps. Finding a cover or searching IGDB without a key offers **Add API key**. The old places show a status line and **Manage in API keys**. Keys stay write-only: the app only learns whether each is set.
- Transitions: a game page grows out of the clicked poster (and shrinks back on close when the poster is still on screen); changing launcher, store or Installed/All fades the old games out and the new ones in; Settings and the keys sheet slide in.
- Micro-interactions: buttons, cards, rail and menu items shrink slightly while pressed and ease back (no bounce). Covers, heroes, logos and previews show a small spinning ring while loading (not at all for cached images), then fade in.
- New **Settings → Appearance → Reduce motion**: Full (always animate), Follow Windows (default), Reduced (short fades only) or Off (no animation at all). When Windows' animation effects are off, Follow Windows reduces motion and Settings says so; choose Full to animate anyway.
- Game page open and close are clearer and smoother: the poster lifts, its cover grows into the hero (cropped, never stretched) while the library dims and recedes, then the title, play bar and content follow one after another; closing shrinks the art back onto the poster. All motion uses clean ease curves, with no springy overshoot.
- Technical: the separate settings window and its page are gone, so the `settings` window label is removed from the capabilities (no permission was added); `settings_open` focuses the main window and sends it a `settings:open` event with the section (now also `api-keys`). New stored setting `motion` (older settings default to following Windows).

## [0.5.1] — 2026-11-16

### Custom launchers
- Fixed: pressing **Play** on a game of a custom launcher that wasn't running opened the launcher twice and the game never started. Game Lobby started the launcher on its own, then on **Continue** started it a second time with the game as an argument, which launchers that aren't single-instance, or don't understand those arguments, can't handle. A launcher set to run games through its program is now started once, with the game, and no longer waits.
- New: each launcher with a program has a start mode, chosen under **When you play one of its games**:
  - **Open it first, then start games directly (for launchers you sign in to)**, the default for new launchers: Play opens the launcher on its own, with no arguments, when it isn't running, shows **Waiting for …** until you continue (once you're signed in), then starts the game itself from its own file, exactly like a local game or ROM: the `.exe` in its folder, a plain or confirmed shortcut, or a ROM with its emulator (a ROM no emulator fits names the file). When the launcher is already running, the game starts right away. The launcher's arguments aren't used, identifiers aren't available, a game added as a folder can't start this way, and launch options are the game's own `.exe` options.
  - **Start games through it (it takes the game as an argument)**: what launchers did before. Launchers you already have keep this mode.
  - Changing the mode shows a Windows confirmation saying what will run, and linking a game to a launcher one click at a time is only possible for the mode you confirmed. The link dialog and the waiting dialog describe the launcher's mode.
- Launchers that are opened first:
  - Linking one to a game of another launcher always shows its Windows dialog, which says the game will start from that launcher's file directly, outside that launcher; confirming it doesn't count as confirming the launcher for later links. The launcher's own games aren't affected.
  - The link dialog says a ROM starts with its emulator, and names the emulator when one is set up.
  - The save dialog also lists the arguments kept for **Start games through it**, marked as not used now, so everything stored is shown when you confirm it.
  - A ROM with launch options left from **Start games through it** is refused with a message saying to remove them, instead of starting without them. An internet shortcut (`.url`), read again at every Play, must open a store's plain game link (like `steam://rungameid/400`). A game's launch options are kept when its file is written with a different case or `/` instead of `\`.
- The user guide's launcher argument examples no longer read like options every launcher supports: check your launcher's own documentation for its command line.
  - Note: the start mode is a new `startMode` column of `custom_launchers` and of `launcher_confirmed` (no schema version change; launchers and confirmations stored before count as **Start games through it**). Backups include the start mode only for launchers that are opened first. Older versions of Game Lobby ignore the column, so they run the games of a launcher that is opened first through its program with its arguments, and refuse to import a backup that contains such a launcher.

## [0.5.0] — 2026-11-16

### Library
- Optional: Steam games you own but haven't installed. Add your own free Steam Web API key and SteamID64 under **Settings → Libraries → Steam** and they show under All, marked not installed. Without a key Steam stays installed-games only. Installed state from the local scan wins, nothing you changed is overwritten, Steam is asked at most every 30 minutes, and a failed check (offline, private profile, rejected key) keeps the previous list and explains why. The key and SteamID are encrypted by Windows and left out of backups, logs and diagnostics; **Remove** clears them and the games they added.

### Linked games and launch routes
- Launch routes can have their own name (up to 60 characters), shown after the store or launcher under **Play from**, in the game page's **Stores** list and on the **Play** button, so two routes of one store read apart: **Xbox · Java Edition** and **Xbox · Bedrock Edition**. Names are display only (they never change what runs) and rescans keep them.
- **Link other games…** links two or more entries, including entries from the same store, after a review step: it lists what is combined and lets you choose the kept entry, title (or your own), cover, page art, notes and score, IGDB details and favourite, and shows the resulting routes with suggested names (from known Xbox packages such as Minecraft's, from the entries' own titles, or from `.exe` names). Every route keeps its own store, target, install state and playtime; sessions, screenshots and memories move over, playtime is added up, and details you didn't pick are kept for unlinking instead of deleted.
- Unlink a route from the game page: a route that came from a linked entry brings that entry back with its own title, cover, favourite, notes, page art, IGDB match, screenshots, memories, the sessions it brought and its playtime. Sessions played after linking stay with the linked game (sessions are recorded per game, not per route). A route that was never linked becomes a new game of its own. Unlinked games aren't suggested as duplicates again. Entries can be unlinked in any order and each gets its own details back, an entry linked into a game that was then linked into another comes back too, and an entry a scan or backup adds back as a game gets its own details back.
- Unlinking never takes a route the kept game already had: when a linked entry had a route the game already had, the route stays and the entry comes back with a copy. Unlinking is refused while the game is running. Launch options are also refused for shells, script hosts, interpreters and programs in the Windows folder, and for proxy, host-rule, certificate and `--require` options, and paths hidden behind `;` or `,` in a value are checked.
- Launch options per route for games Game Lobby starts from their own `.exe`: checked like emulator and launcher arguments (no shell, no code-loading or debugging options, files only inside the game's folder), at most 24 options of 200 characters (1,000 in all), shown in a Windows confirmation with the exact program and arguments before they are saved, and checked again at every launch. They only run on the `.exe` they were confirmed for: options from a backup or an older version, or on a route whose `.exe` changed, show **Needs confirmation** and don't run until confirmed again. Moving the `.exe` in library health drops them, and merged routes keep them only for the same `.exe`. Store, Xbox and emulator routes, and launchers without a program, say where to set options instead.
- Library health and scan duplicates only suggest linking; **Link…** opens the review. Launcher games folders no longer add a found game to an existing game just because the titles match: it is added on its own and offered under Review to link.
  - Note: linked entries are recorded in a new `game_links` table and confirmed launch options in `launch_args_confirmed` (no schema version change; confirmations are never part of a backup). Backups include route names, linked entries and the notes, controller details and page art kept for them; a restore never replaces a live link and skips linked entries that don't fit the library. Older versions of Game Lobby show linked games and their routes, but drop route names when they next save a game, can't unlink, start local games without their launch options, and refuse to import a backup that contains route names or linked games.

### Fixes
- Choosing a match with **Find details on IGDB** also renames the game to the IGDB name. Automatic matching never renames, and later scans keep the new name.
- Game page heroes follow the art's own shape, so much less is cut off, and Steam games use Steam's double-size hero when it has one, so the hero is sharper.
- Store games whose install folder has nothing to start (for example only DLL files) no longer show as installed. Folders on a drive that isn't connected are left as they are.
- Clearer installer wording when an older version is installed: the screen says your library is kept, the choices read "Uninstall the old version first (your library is kept)" and "Install over the old version", and the uninstaller's box now reads "Also delete my library and settings (permanent)". In-app updates skip these screens and never delete data.

### Custom launchers
- **Link to launcher**: link any game to a custom launcher in one click, from the game page's **⋯** menu, the game page's **Launchers** block, or a library card's right-click menu. The list shows each launcher with its icon and colour, greys out the ones that can't take the game (with the reason), and shows **Linked** with **Unlink** for the ones it is linked to. Game Lobby picks what the launcher gets from the game itself (its first way to start first; a file, then a folder, then a store id) and says **Linked to … Play now starts it through …** with **Undo**; **Choose which file…** appears only when the game offers several. No Windows dialog is shown when you already confirmed that launcher's program, arguments, working folder and target kinds on this PC when saving it; a launcher saved by an older version, restored from a backup or changed without its dialog asks once, and then links in one click. Both the launcher's save dialog and that link dialog say right after the program, where a long argument list can't push it off screen, that confirming lets any game in your library be linked later without asking, and name every kind of target the launcher takes (file, folder, store id). A link dialog too long to read whole still links the game but leaves the launcher unconfirmed, so the next link asks again. Launch options are added afterwards under **Play from** and are always confirmed. A store link can't be given a store id the game doesn't already have, so linking can only pass a launcher an id the game really has.
  - Note: confirmed launcher commands are recorded in a new `launcher_confirmed` table (no schema version change; never part of a backup, and a restored launcher is confirmed again on its first link). The game page's **Add to a launcher…** picker and its launch options box are replaced by **Link to launcher…**.
- Add any game already in your library to any custom launcher from its game page (**Launchers → Add to a launcher…**). The game shows under that launcher, and Play runs it through the launcher's program with the game's own file, install folder or store id (whichever the launcher takes), after a Windows confirmation showing exactly what will run. The game's original way to start stays under "Play from", the Play button names the launcher, and removing it from the launcher takes away only what was added. Assignments survive rescans and are included in backups. When none of the game's targets fit the launcher, the page says why instead of adding a route that can't work.
- Playing through a custom launcher whose program isn't running starts the launcher on its own first and shows "Waiting for …" until you press Continue (it shows when the launcher is running). The waiting launch can be continued once, within five minutes. Stores and emulators start as before.
  - Note: older versions of Game Lobby show a game added this way as a normal game of that launcher (without the remove option), and refuse to import a backup that contains one, so avoid going back to an older version after using it.
- Launch options for games played through a custom launcher with a program: extra arguments for one game, added after the launcher's own arguments and the game's target. They follow the launcher-argument rules (no shell, no code-loading or debugging options, files only inside the launcher's folder, no `{` or `}`), at most 24 options of 200 characters (1,000 in all), and a Windows dialog shows the program, the whole numbered command line (saying which arguments are the game's options) and the working folder before they are saved. They are bound to exactly that command line: changing the launcher's program, arguments or working folder, or the game's target, shows **Needs confirmation** and Play refuses until you confirm again. A launcher that isn't running yet is still started on its own without arguments, and **Continue** checks the options again. Launchers without a program don't take options.
- Easier launch options: the game page shows the chosen route's options under **Play from** (**Options: -windowed -nosplash**) with **Edit**, a **Launch options** button when it has none, and **Needs confirmation** with a one-click **Confirm…**. The editor checks the text as you type, shows why it would be refused or what will run, has an example and links to the user guide. **Add to a launcher…** has an optional **Launch options** box, confirmed in the same Windows dialog as the new route.
  - Note: launch options on launcher routes are stored in the route's existing launch options field, which backups already include; confirmations are kept in `launch_args_confirmed` as before (never in a backup), so restored options need confirming. Older versions of Game Lobby keep these options but start launcher games without them.

## [0.4.0] — 2026-11-15

The first public release. Version 1.0.0 follows once the release pipeline and hands-on test pass are done.

### Library
- Detects installed games from Steam, Epic Games, GOG, Xbox / Microsoft Store, Ubisoft Connect, EA app, Battle.net, itch.io and Amazon Games, grouped by library.
- Scans your own game folders and emulator / ROM folders, including hidden and system folders and a games folder that contains the emulators folder.
- Emulator profiles with ROM routes; duplicate emulator entries show the ROM file name.
- Custom games from folders, shortcuts and programs.
- Custom launchers: your own launcher with its name, icon, colour, program and arguments, its own side-rail entry and library filter. Changes to its program or arguments are confirmed in a Windows dialog.
- Custom launcher games folders: scan an app folder for PC games, shortcuts, emulators and ROMs in one go. Emulators are registered without duplicates, ROMs are matched to them (uncertain matches go to Review), games already in the library get an extra "Play from" route named after the launcher, and rescans never touch your titles, covers, favourites, notes or playtime.
- Custom launchers can allow several target kinds (file, folder, identifier), and the program is optional: without one, games run directly with the launcher as their label.
  - Note: older versions of Game Lobby treat a launcher's games folders as plain game folders (without the launcher's label or routes), so avoid going back to one after adding them. Launcher games folders, like other library folders, aren't included in backups: add them again after restoring one.
- Storage view: install sizes per game, a total, and "Uninstall…" that hands off to the game's own launcher.
- Recently added shelf for newly discovered games.
- Library health: finds missing or moved files and duplicate games or launch routes, and helps repair them.

### Game page
- Artwork from SteamGridDB (covers, heroes and logos, 50 per page with "Load more"), including animated art.
- Game details from IGDB: description, genres, developer, publisher, ratings, screenshots and time to beat, with a guided Twitch setup.
- Screenshot wall with your own screenshots and Steam screenshot import.
- Your score, notes, memories, and controller details (support level from Steam, preferred controller, input notes).

### Play tracking
- Playtime for games started from Game Lobby or detected while it runs.
- Full play history with exact start and end times, editing and deleting sessions, crash and shutdown recovery, a journal per session, and share or export as text or Markdown.

### App
- Game Lobby minimizes when a game starts (can be turned off).
- Only one copy runs at a time; opening it again brings up the running window.
- Log file and "Copy diagnostics" for bug reports, with keys and personal paths left out.
- Signed automatic updates.
- New GL app icon.

### Safety
- Game Lobby's interface can never choose which program, link or arguments the app runs: programs and folders come only from Windows file pickers, store links must match one known shape per store, and emulator arguments are checked.
- API keys are stored encrypted with Windows DPAPI and never logged.
- The library database is checked at every start and repaired automatically if it is damaged; backups use SQLite's own backup method.
